# Как устроен soiskatel

## Два плагина в одном marketplace
- `soiskatel`: пять скиллов на Markdown (`profile`, `vacancy`, `letter`, `tracker`, `interview`). Работают без установки чего-либо ещё.
- `soiskatel-mcp`: необязательный MCP-сервер `Soiskatel.Mcp` на .NET 10. Запускается командой `dotnet dnx Soiskatel.Mcp@<версия> --yes`, версия зафиксирована в `plugins/soiskatel-mcp/.mcp.json`.

## Граница между кодом и промптом
Проверки, у которых есть точный ответ (тире, стрелки, невидимые символы, лимит длины, разрешённые смены статуса, воронка), сделаны кодом и покрыты тестами. Оценки, которые требуют понимания текста (подходит ли вакансия, сильное ли письмо), делает модель по правилам из скиллов.

## Сервер
- `Storage`: всё происходит внутри папки поиска (`SOISKATEL_HOME` или рабочая папка); пути наружу отклоняются; запись атомарная, прошлая версия в `.bak`.
- `TextCheck`: правила письма.
- `Tracker`: модель отклика, таблица `applications.md` (строки, которые не удалось разобрать, сохраняются как есть), переходы статусов, названия компаний, воронка.
- `Tools`: тонкие обёртки MCP. Ошибки логики возвращаются как ошибки инструмента с понятным текстом.

## Тесты
- xUnit на каждое правило, тест «прочитать, записать, прочитать» для таблицы, поддельные часы для «без ответа 7 дней».
- Архитектурные тесты (NetArchTest): типы сервера не зависят от `System.Net.Http` и `System.Net.Sockets`; логика не зависит от MCP SDK.
- Сквозные тесты: сервер и клиент MCP в одном процессе через каналы в памяти.
- CI: сборка, тесты, gitleaks; публикация в NuGet по тегу `v*` только если версия совпадает во всех пяти файлах.
- Манифесты плагинов: `claude plugin validate --strict` проходит локально; задание в CI добавлено, но ещё не запускалось на GitHub. Если в CI команде понадобится вход в аккаунт, задание убирается, а проверка выполняется локально перед каждым релизом.
